# Repository instructions

These are the canonical working instructions for coding agents in this repository.

## Working agreements

- Preserve unrelated user changes in a dirty worktree.
- Keep changes focused and add or update tests when behavior changes.
- Run the narrowest relevant checks while iterating, then `uv run ruff check . && uv run pytest` before handing off code changes.
- Do not run live tests, ingest data, deploy infrastructure, create releases, or mutate AWS resources unless the user explicitly asks.
- When architecture, commands, environment variables, deployment, or operational constraints change, update this file in the same change. Keep it agent-neutral and avoid duplicating its guidance elsewhere.

## Project

pep-oracle is an **MCP server** (plus a Fargate ingestion job) that answers US-politics questions over the "PEP with Chas and Dr Dave" podcast using RAG. Episodes are transcribed (faster-whisper on Modal) + diarized, chunked, embedded (AWS Bedrock Titan), and published as a versioned corpus artifact in S3. A frontier model calls the single MCP tool to retrieve grounded excerpts. Deployed AWS-only (serving Lambda + Fargate ingestion); there is no longer a user-facing CLI query path or web GUI.

## Architecture

`server.py` (FastAPI) mounts the MCP server and exposes only `/health` + `/version`; `server.handler` is the Lambda entrypoint — it routes the EventBridge warmer sentinel (`{"pep_oracle_warm": true}`) to an in-process search and everything else to the Mangum ASGI adapter. The two pipelines are ingestion (Fargate `ingest-artifact`) and retrieval (the MCP tool).

**Ingestion** (`ingest_artifact.py` orchestrates):
load current S3 corpus → find new feed episodes (`feed.py` RSS parse) → per episode `ingest.episode_chunks_and_embeddings`: **concurrent** [`transcripts/manager.py` (Whisper via `cloud/transcribe_modal.py`) ‖ `transcripts/diarize.py` `get_speaker_segments` (pyannote via `cloud/diarize_modal.py`)] → `apply_diarization` (aligns speakers + maps host names) → `chunking.py` (time-window chunks with overlap) → `embeddings.py` (Bedrock Titan) → corpus rows (`store._chunk_metadata`) → merge + publish `vN+1` (atomic `current.json` flip). The serving Lambda TTL-refreshes within about 5 min. No ChromaDB anywhere.

**Hybrid retrieval** (`hybrid.py` + `lexical.py`): semantic embeddings blur distinctive terms (proper nouns, bill names) that a politics podcast is full of; BM25 (`lexical.BM25`, with digit→word `normalize_numbers` so "day 2"≈"day two") nails those but is blind to paraphrase. `hybrid_search` ranks candidates by both and merges with **weighted Reciprocal Rank Fusion** (`SEMANTIC_WEIGHT=0.8`, tuned via the eval harness — leans semantic so BM25 rescues distinctive-term queries without diluting topic queries), returning query-shaped dicts with a rank-based `distance` so the temporal layer treats the fused rank as relevance. The BM25 index + corpus is cached per `(collection name, corpus version)` (with a chunk-count staleness check) and rebuilt on each corpus version swap; exhaustive local ranking is fine at this corpus size (≤about 10k chunks). The index is normally **shipped prebuilt in the artifact** (sidecar, decoded in ~1s) so the cold start skips the ~2.7s rebuild — `_load_corpus` adopts `collection.prebuilt_bm25` when present (and `N==count`), falling back to `build_bm25(docs)` only when no usable index loaded (so `hybrid.bm25_build` in logs is an ops signal). `build_bm25` is the single canonical builder shared by the write/serialize and serve-fallback paths so a prebuilt index can never drift from runtime preprocessing.

**Temporal reranking** (`temporal.py`): recency must be *intent-gated*, not global — a blanket recency prior makes old-but-relevant content unretrievable (the "temporal event horizon"). `intent` ∈ {`current`, `historical`, `evolution`, `prediction`, `timeless`}: `current` → exponential recency decay (`HALF_LIFE_DAYS`), newest-first, NO hard date cut; `evolution` → spread across episodes, chronological; `prediction` → relevance, chronological (so the reader sees prediction→outcome); `historical`/`timeless` → pure relevance, newest-first.

**MCP server** (`mcp_server.py` + `oauth.py`) — the core product:
Exposes a single tool (Python `search_pep`, exported as `search_us_politics_commentary`; `search_pep(query, top_k=5, episode_number=None, intent=None, after_date=None, before_date=None)`) over the official `mcp` SDK's Streamable HTTP transport. It embeds the query (Bedrock) → `hybrid_search` → `temporal.select_for_intent`, returning `{"corpus": {newest/oldest episode}, "results": [citation dicts: episode number, title, date, timestamp, speakers, excerpt]}`. Default ranking is relevance, so the *caller* (a frontier model) scopes via `episode_number` (use `corpus.newest_episode` for "the latest episode") and shapes recency via `intent`; `evolution`/`prediction` return oldest-first; `after_date`/`before_date` hard-filter a window. The retrieval source is always the corpus artifact via `get_serving_corpus` → `corpus.current_corpus` (TTL-refreshed `InMemoryCorpus`, atomic version swap). Mounted at `/mcp` by `server.mount_mcp_if_configured()`, gated by JWT bearer verification against an in-app OAuth 2.1 + DCR provider (`oauth.py`, HS256 access tokens, 60s auth codes, 30d rotating refresh tokens with family revocation on reuse). Discovery doc at `/.well-known/oauth-authorization-server`; routes under `/oauth/{register,authorize,token,revoke}`. The signing key is resolved via pluggable `signing.py` (`local` env→file→generate, or `ssm` SecureString); `/oauth/authorize` is gated by pluggable `authorize_gate.py` (`TrustedUpstreamGate` default; `CognitoGate` brokers a Cognito Hosted-UI login → `/oauth/authorize/callback` verifies the ID token via the pool JWKS + email allow-list, carrying the MCP params in a stateless HS256 login-state JWT so PKCE survives the round-trip). Mount requires `PEP_ORACLE_PUBLIC_URL` plus either `PEP_ORACLE_OAUTH_TRUSTS_UPSTREAM_AUTH=1` or `PEP_ORACLE_AUTHORIZE_GATE=cognito`; refuses to start otherwise so `/oauth/authorize` can't accidentally be exposed open. Serves stateless (mcp SDK ≥2 `MCPServer`; `stateless_http=True` is a transport param passed to `streamable_http_app()` at mount time, not a constructor arg) so any Lambda container handles any request. **`GET /mcp` is declined with 405** by `server._mcp_stateless_asgi` (after the bearer gate, so an unauthenticated GET is still 401): Streamable HTTP's optional server→client SSE stream is held open by the SDK until the client disconnects, which under Mangum means the invocation never returns and Lambda kills it at the timeout — one burned concurrency slot per attempt. A stateless server has no server-initiated messages to push, and the spec permits 405. **`json_response=True` (also a `streamable_http_app()` transport param) closes the same hazard on the POST path** and is not optional here: with the SDK default (`False`) a POST carrying a JSON-RPC *request* is answered with a `text/event-stream` response instead of plain JSON, and Mangum's buffering turns a stream that doesn't close into a 30s timeout — 46 of them in the fortnight to 2026-08-28, each a 503 to the client and one concurrency slot held, diagnosable only from the access logs because no exception or timing phase is ever logged (the tool never runs). **`POST subscriptions/listen` is declined the same way** (JSON-RPC `-32601`, matched on the required `MCP-Method` header so no body read consumes the SDK's `receive()`): the 2026-07-28 revision moved the server→client notification stream off GET and onto that POST, whose *response is* the stream, and `json_response=True` does **not** cover it — the SDK exempts that one method from the JSON fast path by design, because a listen response is a notification stream. This server advertises no `listChanged` and no resource `subscribe`, so the stream has nothing to carry. It caused 45 timeouts in the six days to 2026-08-28, starting 08-25 when a client first negotiated the revision (visible in the access logs as POST /mcp 400s appearing alongside the 30s 503s). Note Mangum's `receive()` blocks forever once the single queued `http.request` is consumed, so any SDK path that awaits a disconnect event hangs — treat that as the general shape of this class of bug. All three switches are guarded by tests in `tests/test_mcp_server.py`; the GET and listen ones hanging rather than failing are themselves the regression signal.

## Key design decisions

- **Corpus artifact** (`corpus.py`): a versioned immutable parquet (`<CORPUS_URI>/corpus/vNNNN.parquet` + `.manifest.json` + prebuilt sidecars — BM25 index `vNNNN.bm25.zst`, embedding matrix `vNNNN.emb.zst` (raw float32; lets the parse skip the parquet's embedding column, its dominant decode cost) — + mutable `current.json`) re-loadable into an `InMemoryCorpus` that is a drop-in for `hybrid_search`/`store.get_ingestion_stats`. Sidecars are written before the atomic `current.json` flip (never block publish on failure) and provenance-validated on load against the just-verified parquet sha256 (+ a code fingerprint for BM25); any mismatch → rebuild/decode-from-parquet. `Manifest`/`current.json` are byte-unchanged so a rollback to old serving code is inert. See `docs/aws/prebuilt-bm25-index.md`. It is the **only** serving source (ChromaDB was removed). `corpus.current_corpus()` is the TTL-refreshed, version-swapped serving accessor (`CORPUS_REFRESH_TTL_SECONDS`, default 300s); `corpus._validate_serving` enforces dims + embedder against the manifest at load. `GET /version` reports code (semver + `GIT_SHA`) and corpus (version, episode_range, built_at, embed_model).
- **Bedrock-only embeddings** (`embeddings.py`): `embed_texts()` calls AWS Bedrock Titan (`amazon.titan-embed-text-v2:0`, 1024-dim, region `BEDROCK_REGION`), one `InvokeModel` per text with throttle backoff. There is no local/fastembed path. Query and corpus vectors must come from the same model — the corpus manifest records `embed_model`/`EMBED_MODEL` and the loader validates it.
- **Incremental ingestion**: episodes tracked by GUID + episode number in corpus metadata; already-present episodes are skipped. **Selection is newest-forward by default** (only numbered episodes *newer* than the corpus max) so one permanent back-catalogue gap (eps 179–216 were never transcribed; unnumbered "EXTRA" bonus episodes) can't turn every daily run into a fragile all-or-nothing job — publish is one `current.json` flip after the whole loop. `--backfill` (operator-run, supervised) ingests every feed episode the corpus lacks.
- **Cloud transcription**: Modal A100 GPU (`cloud/transcribe_modal.py`), `faster-whisper large-v3-turbo`. Modal fetches audio from the RSS enclosure URL — no local audio download. Weights persist in a `modal.Volume` (`pep-oracle-whisper-cache`). About 1 min per 2-hour episode; runs concurrently with diarization. Deploy with `modal deploy cloud/transcribe_modal.py`. Fail-fast (no fallback). Transcript cache at `~/.pep-oracle/cache/transcripts/{guid}.whisper.json`.
- **Cloud diarization**: Modal A100 GPU (`cloud/diarize_modal.py`), pyannote. Audio fetched from the RSS enclosure URL. Weights persist in a `modal.Volume` (`pep-oracle-pyannote-cache`, mounted at `/cache/hf` via `HF_HOME`). About 2–3 min per 2-hour episode, concurrent with transcription. Deploy with `modal deploy cloud/diarize_modal.py`. See `cloud/README.md`. Diarization cache is v2 `{segments, clusters}`; loader is back-compatible with old bare-list caches.
- **Speaker name mapping** (`transcripts/diarize.py`): pyannote over-segments this audio and can't cluster Chas vs Dave, but per-cluster *embeddings* separate hosts cleanly. `map_speaker_names` matches each cluster to reference voices in `speaker_profiles.json` via `assign_by_voice` (`VOICE_MATCH_MAX_DISTANCE=0.5`), collapsing a host's over-split fragments and excluding guests; fallback `assign_substantive_speakers` uses speaking-time when no references exist. Do NOT cap `max_speakers` (it merges the hosts). The Fargate ingest reads references from `s3://…/refs/speaker_profiles.json` (`SPEAKER_PROFILES_URI`); the local file lives at `~/.pep-oracle/speaker_profiles.json`.
- **Speaker metadata**: diarized chunks store boolean `has_speaker_chas`, `has_speaker_dave`, etc. (mapped host names, never raw `speaker_N`) plus a `speakers` JSON string of turn boundaries for hybrid speaker trimming at query time (`store._chunk_metadata`).
- **OAuth store seam** (`oauth_store.py`): clients + single-use auth codes + refresh tokens behind `OAuthStore`; `PEP_ORACLE_OAUTH_STORE` selects `sqlite` (local default, `~/.pep-oracle/oauth.db`) or `dynamodb` (Lambda). Rotation is race-safe via a conditional `revoke_refresh` (won/lost) — concurrent refreshes → exactly one rotation, loser gets a clean 400, no spurious family revoke; genuine reuse revokes the family. DynamoDB = single table + `family-index` GSI + native TTL; `DynamoDbStore.ensure_table()` is local/moto only (prod table from CDK). Contract tests (`tests/test_oauth_store.py`, moto) run every behavior against both backends.
- **MCP tool metadata are load-bearing and must be front-loaded**: some MCP clients *defer* tools — they initially see only the tool name and truncated metadata, so trigger language in a trailing paragraph may never influence selection. In `mcp_server.py`, the tool is exported as `search_us_politics_commentary` (`SEARCH_TOOL_NAME`), and `SEARCH_PEP_DESCRIPTION` leads with the user goal (including indirect US-politics questions and shared news articles), distinguishes podcast commentary from current factual sources, and states the non-US-politics boundary before source/mechanics detail. The tool also exports a human title, read-only/closed-world annotations, documented constrained inputs, and a structured citation output schema; `tests/test_mcp_server.py` locks down the complete `tools/list` contract. If metadata change, keep the trigger in sentence one and re-test direct, indirect, and negative prompts. Client-side retrieval can't be forced — good metadata only raises the odds.
- **`/oauth/authorize` is gated at the edge, not in app** (default `trusted_upstream` gate): the handler auto-approves any well-formed request, so the deployment MUST sit behind an upstream authenticator restricting who can reach the route (e.g. a Cloudflare Access Self-hosted app scoped to `/oauth/authorize`). `/oauth/register`, `/oauth/token`, `/.well-known/...`, and `/mcp` must stay open at the edge — they're server-to-server or PKCE/JWT-protected. `PEP_ORACLE_OAUTH_TRUSTS_UPSTREAM_AUTH=1` is a fail-closed switch asserting the operator wired up the upstream gate; the app refuses to mount OAuth routes without it. Alternatively `PEP_ORACLE_AUTHORIZE_GATE=cognito` is an in-app identity gate that removes the external-edge dependency.
- **Cold-path timing** (`timing.py`): `timed(phase, **fields)` logs one structured `timing phase=<name> ms=<n>` line per phase to the `pep_oracle.timing` logger. The MCP search path is instrumented (`search.*`, `embed.client_init`, `corpus.*` incl. `corpus.index_download`/`corpus.index_decode`/`corpus.emb_download`/`corpus.emb_decode`, `hybrid.bm25_build`) so a cold/first request's breakdown — S3 download, parquet parse incl. the arrow→numpy embedding load, prebuilt-index decode (or fallback BM25 build), Bedrock embed — is readable in CloudWatch (Lambda's own `Init Duration` covers the import/INIT phase). Corpus load is **lazy on first request**, so the first `/mcp` search pays the corpus + index build; those phases also recur on each TTL refresh. In prod a **scheduled warmer** (EventBridge `ServeWarmSchedule`, rate 4 min, sentinel event `{"pep_oracle_warm": true}` routed by `server.handler` to an in-process `search_pep` — `warm.search` phase) keeps one container's corpus resident and absorbs the TTL refresh, because at this traffic level every user search would otherwise be a true cold start (~8 s; dominated by container-image lazy-load page faults that column pruning can't fix). Keep the corpus lazy — do NOT warm at INIT (it would tax the many cheap health/discovery cold starts). Three alarms cover the ways warming dies silently: Lambda `Errors` (the warm search raised — `server.handler` deliberately lets those propagate, and Mangum swallows ordinary request errors into 500s), `Invocations < 10/hour` with `treat_missing_data=BREACHING` (rule disabled/deleted — the warmer alone guarantees ~15/hour regardless of user traffic), and EventBridge `FailedInvocations` (delivery failed, e.g. throttling against the account's concurrency=10). `Errors` is **not** warmer-exclusive despite that being its most likely cause: a Lambda timeout counts too, so `ServeFnTimeoutAlarm` (Lambda `Duration` Maximum > timeout − 2s) separates "blocked, never responded" from "raised" — keep both alarm descriptions naming both causes. See `docs/aws/cold-path-measurement.md`.
- **Episode number regex** handles both English `(Ep NNN)` and Spanish `(Episodio NNN)` title formats.
- **Data dir**: local state lives at `~/.pep-oracle/` (transcript/diarization caches, `speaker_profiles.json`, `oauth.db`); override with `PEP_ORACLE_DATA_DIR`. On Lambda (read-only FS) `DATA_DIR=/tmp` and the corpus comes from `CORPUS_URI` (S3).

## Environment

Required in `.env` (loaded via python-dotenv):
- `MODAL_TOKEN_ID` / `MODAL_TOKEN_SECRET` — Modal credentials for cloud transcription and diarization

Optional:
- `PEP_ORACLE_DATA_DIR` — override default `~/.pep-oracle/` data directory
- `PEP_ORACLE_CORPUS_URI` — base URI of the corpus artifact (S3 in prod; defaults to the data dir)
- `PEP_ORACLE_HOST` / `PEP_ORACLE_PORT` — local server bind address (default `0.0.0.0:8000`)
- `PEP_ORACLE_PUBLIC_URL` — public issuer URL in the OAuth discovery doc; must match the tunnel hostname (e.g. `https://pep-oracle.iicapn.com`). Required to enable `/mcp`.
- `PEP_ORACLE_OAUTH_TRUSTS_UPSTREAM_AUTH` — literal `1` to mount `/oauth/*` and `/mcp`. Asserts an upstream gate protects `/oauth/authorize`. Any other value → mount skipped with ERROR log.
- `PEP_ORACLE_OAUTH_SIGNING_KEY` — HS256 signing key for access-token JWTs. If unset, falls back to `~/.pep-oracle/oauth_signing_key` (mode 0600); auto-generated on first start if absent.
- `PEP_ORACLE_OAUTH_SIGNING_BACKEND` — `local` (default: env/file/generate) or `ssm` (HS256 SecureString from `PEP_ORACLE_OAUTH_SIGNING_SSM_PARAM`, region `PEP_ORACLE_OAUTH_SIGNING_SSM_REGION`). Lambda uses `ssm`; missing/empty param fails closed.
- `PEP_ORACLE_AUTHORIZE_GATE` — `trusted_upstream` (default) or `cognito`. `cognito` enables the in-app one-user Cognito identity gate and does NOT require `TRUSTS_UPSTREAM_AUTH=1`; it needs the domain, client ID, user-pool ID, region, and allowed-email settings. Local development may set `PEP_ORACLE_COGNITO_CLIENT_SECRET`; production receives only `PEP_ORACLE_COGNITO_CLIENT_SECRET_ARN` and resolves it from Secrets Manager.

No host-side ffmpeg required — both Modal images apt-install their own.

## Deployment

The product runs entirely on AWS — the OptiPlex serving/ingest/DNS-rollback fallback was decommissioned 2026-06-09. `infra/` is a CDK Python app (isolated `infra/.venv`, excluded from root pytest via `--ignore=infra`, tested with `cd infra && .venv/bin/python -m pytest`):
- **Serving (Phase 2c)**: `PepOracleCertStack` (us-east-1: Route 53 zone + ACM cert) + `PepOracleProdStack` (ap-southeast-2: KMS, S3 corpus bucket, DynamoDB OAuth table matching `oauth_store.DynamoDbStore`, one-user Cognito pool, container Lambda `pep_oracle.server.handler` fronted by CloudFront → **API Gateway HTTP API** ($default proxy), least-privilege IAM, EventBridge warmer rule `ServeWarmSchedule` + alarms on an own `ServeAlerts` SNS topic — separate from the ingest stack's topic so the stacks stay independently deployable). **Request-level observability**: the HTTP API stage writes JSON access logs to the `HttpApiAccessLogs` group and CloudFront writes standard logs to `AccessLogsBucket` under `cdn/`. These are load-bearing, not decorative — Mangum logs a request only once the app responds, so an invocation that never responds leaves no method or path anywhere in the Lambda logs, and `httpMethod` is what tells a GET stream attempt from an ordinary POST. The format deliberately references **no** `$context.request.header.<name>`: HTTP APIs resolve no arbitrary request header in an access log (`$context.identity.userAgent` is the only header-derived variable), so API Gateway rejects such a format at deploy — it failed the stage update and rolled the stack back on 2026-08-28. The JSON-RPC method is instead logged by the app at ASGI entry in `server._mcp_stateless_asgi` (`mcp request http=… mcp_method=… protocol=…`, `-` for clients on pre-2026-07-28 revisions), which every `/mcp` call needs because they are all POSTs — `httpMethod` cannot separate a `subscriptions/listen` from a `tools/call`, and bodies are logged nowhere. Entry is also the only placement that works: Mangum logs a request once the app responds, which a hung invocation never does, so a line written before dispatch is the one that survives the timeout. `infra/tests/test_prod_stack.py` guards the access-log format against re-adding the header variable, since synth cannot catch what only the service refuses. `AccessLogsBucket` must keep `object_ownership=BUCKET_OWNER_PREFERRED` and SSE-S3 (**not** the CMK): CloudFront's legacy log delivery writes with an ACL and cannot target an SSE-KMS customer key, and gets either wrong by failing delivery silently. Lambda-readiness: per-request stateless MCP session manager (Mangum runs the ASGI lifespan per-invoke), `DATA_DIR=/tmp`, disabled MCP DNS-rebinding host-check + `/mcp`→`/mcp/` normalizer (behind CloudFront→APIGW the Lambda sees the execute-api Host). Account facts: Lambda concurrency=10; public Function URLs blocked account-wide (hence APIGW). Phase 2c documents under `docs/aws/` are historical cutover records. `pep-oracle.iicapn.com` is on AWS (Route 53 NS delegation at Cloudflare).
- **Ingestion (Phase 3, `infra/pep_oracle_infra/ingest_stack.py`)**: daily EventBridge rule → scale-to-zero Fargate task running `pep-oracle ingest-artifact`. Modal tokens via SSM SecureString. The ingest stack imports the corpus bucket + KMS key as **external** resources (bucket by name, key ARN from `cfg.data_key_id`) so deploying it never redeploys the serving Lambda. The Phase 3 runbook is a historical migration/decommission record. A daily inline Lambda (`CorpusStaleCheck`) diffs the corpus manifest's `episode_range` against the live RSS feed (mirrors `feed.EPISODE_NUMBER_RE` + the newest-forward selection rule) and publishes `IngestLagHours` — hours since the *oldest un-ingested numbered episode* was published, 0 when caught up — which is what `IngestLagAlarm` (>48h) watches; it also publishes `CorpusAgeHours` for observability only, un-alarmed, because the podcast goes on hiatus for weeks and an age-based alarm would sit in permanent ALARM and get ignored. Attaching the EventBridge-rule target's resource policy to the `IngestAlerts` SNS topic **replaces** its implicit same-account default policy, so `cloudwatch.amazonaws.com` is granted `sns:Publish` back explicitly — omit that and every alarm action fails silently with an authorization error. (`ServeAlerts` in `PepOracleProdStack` has no EventBridge target, so it keeps the default and doesn't need this.)
- **CI/CD (Phase 4, `.github/workflows/`)**: `ci.yml` gates every PR + push to main (`gitleaks` secret scan + `ruff check` + `ruff format --check` + `mypy src` + root `pytest` + infra `pytest` + `cdk synth '*'` + docker build of both images + blocking Trivy `os,library` scans for high/critical vulnerabilities, with `ignore-unfixed`; no AWS access). It **also runs nightly against main** (`schedule`, 05:00 UTC) plus `workflow_dispatch`: Trivy's verdict comes from a live vulnerability database, so main can turn red with no commit behind it — a newly published fixable HIGH in a base image is enough, and without the nightly run the first sign is an unrelated PR failing at the last step (2026-08-23: six days of a 36-HIGH util-linux stack in the ingest image). `Dockerfile.ingest` therefore runs `apt-get upgrade -y` so each build self-heals against its Debian base; the serving image is Amazon Linux and unaffected. The 05:00 slot is one hour ahead of `release-train.yml`'s 06:00 so a broken main surfaces before the day's release is cut — they are independent, so it does not block the train; retime both together. `deploy.yml` runs on a `v*` tag push, OR via `workflow_dispatch` with a `version` input (e.g. `v1.2.0`) so a release can be cut **without a local machine** — the dispatch path resolves `semver` from the input (not the branch ref), deploys, smoke-tests, then on success tags the deployed commit and pushes the tag with `GITHUB_TOKEN` (which deliberately does NOT re-trigger the `push: tags` event, so no double deploy; needs `contents: write`). It assumes the GitHub-OIDC deploy role from `PepOracleCicdStack` — whose trust is scoped to two `sub`s only, `…:ref:refs/tags/v*` AND `…:environment:production` (never `refs/heads/*`); the `deploy` job declares `environment: production` so BOTH a tag push and a `workflow_dispatch` release from main present an allowed subject — runs `cdk deploy PepOracleProdStack PepOracleIngestStack --exclusively` (deploy context via `env:`, `-c git_sha -c semver`) — `--exclusively` is load-bearing, since `app.py`'s `prod.add_dependency(cert_stack)` would otherwise pull the cert stack into the deploy set and deploy it *first*, inverting the order the WAF's deletion requires, then `scripts/smoke.py` (auth-free: `/health`, `/version` sha+semver match, `/.well-known/...`, `/mcp` no-token→401, retries for cold start). The daily `release-train.yml` dispatches this flow from main when commits are waiting. The release tag surfaces as `GET /version` `code_semver` (`config.SEMVER` overrides the package version). Rollback = re-run `deploy` on the prior `v*` tag (image already in ECR); a re-dispatch of an existing version re-deploys and skips re-tagging. One-time bootstrap: `cdk deploy PepOracleCicdStack` with admin creds (re-run after changing the OIDC trust) + create the `production` GitHub Environment (auto-created on first `deploy` run; on private repos this needs GitHub Pro/Team/Enterprise) + set repo variables `AWS_DEPLOY_ROLE_ARN` + `ALLOWED_EMAIL`. `PepOracleCertStack` stays a manual deploy. Runbook `docs/aws/phase4-cicd-runbook.md`.
- **Hibernation (`hibernate` in `infra/cdk.json`)**: the deployment is currently **hibernated** — `hibernate: true`, deployed 2026-08-29, and `release-train.yml`'s cron is commented out to match. The flag deploys the data + DNS layer only: no serving Lambda / HTTP API / CloudFront / A-alias / warmer / alarms (`PepOracleProdStack` returns at its hibernation gate), no WAF WebACL or logging config (`PepOracleCertStack`), and both ingest schedules `enabled=False`. There is **no live endpoint while it is set**, so `scripts/smoke.py`, the `@pytest.mark.live` smoke tests, and any `deploy.yml` run will fail until it is flipped back. It exists because the bill is fixed per-resource charges rather than usage (the WebACL alone is ~$7.85/month unassociated; the whole serving tier is free-tier at this volume), and because `cdk destroy` is a one-way door here: the retained data resources have fixed physical names (corpus bucket, OAuth table, Cognito domain prefix, client-secret name), so destroying orphans them and the next deploy collides re-creating them. Order matters in both directions — hibernate prod before cert (a WebACL cannot be deleted while a distribution is associated), restore cert before prod (the distribution needs the ACL ARN) — and getting it wrong fails *silently*: CloudFormation retries the blocked WebACL delete through its cleanup phase and then **orphans** it, still billing and no longer visible to any `cdk deploy`, which is what happened on 2026-08-29 and needed a manual `aws wafv2 delete-web-acl` to clear. Always pass `--exclusively`. The corpus, DNS, cert, OAuth table and Cognito user all survive, so restore is a flag flip plus a redeploy. Contract tests in `infra/tests/test_hibernate.py`; runbook `docs/aws/hibernation-runbook.md`.

## Testing

Tests use fixtures in `tests/fixtures/` (RSS XML). External APIs are mocked, including Modal — `pep_oracle.transcripts.whisper.modal` / `pep_oracle.transcripts.diarize.modal` are monkeypatched with a fake whose `Function.from_name(...).remote(...)` returns fixture dicts.

Tests marked `@pytest.mark.live` hit real APIs/data and are excluded by default (`pytest -m live` to include) — they exercise the long-lived server + real corpus where integration bugs actually live:
- `test_smoke_live.py` — hits the running server; `/mcp` rejects no-token (401) and accepts a minted JWT without a 421. Override target via `PEP_ORACLE_SMOKE_URL`.
- `test_data_integrity_live.py` — reads metadata from the current corpus artifact (`config.CORPUS_URI`, the same `InMemoryCorpus` the MCP tool serves) and asserts diarized episodes expose mapped `has_speaker_chas`/`has_speaker_dave`, not raw `has_speaker_speaker_N`.
- `test_eval_retrieval_live.py` — retrieval-quality regression guard (hybrid recall@10/MRR over the real corpus). Quality is measured by `eval_retrieval.py` (phrase-grounded, type-tagged query set; `pep-oracle eval-retrieval` prints recall@k/MRR).
